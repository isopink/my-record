Overview

A Crazyflie 2.1 with a Flow deck that takes a command such as go from A to C and flies between rooms on an IFC-based 3D dynamic scene graph. Out come voxel paths and simulated flights in MuJoCo.

Scope
building the graph and lab data are outside this repo
Method
rule parser with optional LLM fallback, voxel path with a 25 cm wall margin
Ran on
MuJoCo on generated test buildings; the real drone flew hover and forward tests only
Shown at
lab demo planned for the end of November 2026

Problem define

The Flow deck has no obstacle sensing, so collision avoidance has to come from the graph's voxel states. In the dark the drone lost its way and crashed.

  • 201 mm: height sensor stuck at this value during the dark flight
  • 65535: motor output saturated at maximum during the dark flight

Solution

A pipeline from command to goal rooms, room order, voxel path and flight in MuJoCo or on the drone, landing if it leaves the plan. Route flight on the real drone is not yet tested.

Process

  1. Fly. Hover and forward tests on the real Crazyflie, with flight logging.
  2. Fail. A flight in the dark diverged and crashed; pre-flight checks for Flow deck, battery and height sensor were added.
  3. Plan. Goal parsing, room ordering and a voxel path with a 25 cm margin on fake and IFC graphs.
  4. Simulate. A MuJoCo backend flies corridor and stairwell routes; the flight monitor aborts and lands past 0.5 m deviation.

Lesson

Simulation has no sensor model, so it does not reproduce Flow deck drift.

Only scripts/hover_test.py has flown; backends/crazyflie.py is not flight-tested. Hover and forward distances are the drone's own estimates, not tape measurements. The 3DDSG and the Multi-ranger deck had not arrived.
