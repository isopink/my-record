Overview

A TurtleBot3 Waffle Pi patrols a room and stores each desk object as a CLIP embedding, map position, timestamp and existence confidence. Given an English description, it drives to the best memory with Nav2 and re-checks the live view.

Shown at
Intelligent Robotics, University of Seoul, fall 2026; demo 2026-11-26
Method
Kalman or EKF position fusion, Bayes existence update, CLIP similarity times confidence
Hardware
Jetson Xavier NX on the robot, RealSense or C920 camera
Ran on
Windows PC and CI only; nothing has run on the real robot yet

Problem define

A 2D LiDAR cannot range objects on a desk, and fixed-class detectors cannot answer free-form descriptions. Moved objects leave stale memories.

  • 43.0% top-1 for label-match search, depth mode, toy world
  • 50.0% top-1 on moved objects with a memory that only appends

Solution

An object memory package, ROS 2 nodes and robot scripts that turn an English query into Nav2 goals with a live CLIP re-check. Results so far come from a toy world, not the robot.

Process

  1. Propose. Chose desk objects, a raised camera mast, English CLIP queries and two camera modes, depth and no depth.
  2. Prototype. A teammate built a Jetson CLIP test and a camera-only finder; detectNet ran at about 30 FPS in the labs.
  3. Build. Eight work branches built memory, geometry, search, vision worker, ROS 2 nodes and robot scripts, merged on 2026-11-16. src/objmem/,
  4. Fix. An hfov of 1.2 rad gave objects outside the image negative Bayes updates; replaced by 0.96 rad.

Lesson

Everything passes on a PC; nothing has run on the real robot yet.

The toy world has perfect localization, no occlusion and synthetic embeddings, so its absolute numbers mean little. Memory thresholds such as cos_thresh 0.8 are guesses. Every robot script, Nav2 goal and real camera call is still unverified.
