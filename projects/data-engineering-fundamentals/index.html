Built with

Overview

This is a record of study, not a project with a result. The author followed a 16-week course and kept the course files, four class recordings and one practice environment of their own.

Course
Fundamentals of Data Engineering (Korean title 데이터 엔지니어링 기초).
Run by
BDAI society, regular course, AI track.
Length
16 weekly sessions of one hour, Thursday 23:00 to 24:00.
Format
live online classes over Zoom, with the recording shared for one week after each class. Labs in local VS Code for the first half and in Databricks Free Edition for the second half.
Assessment
none described in the syllabus, which sets attendance rules only (more than 10 minutes late counts as absent).

Process

Modules, in syllabus order. Topics are named as the course names them.

  1. Week 1. Role of data engineering and the course flow: data pipeline basics, data lake, warehouse and mart, ETL and ELT, OLTP and OLAP, row and column formats, Parquet, partitioning.
  2. Week 2. Python virtual environments: why they are needed, package management with pip and requirements.txt, registering the environment in VS Code and Jupyter. Hands-on work below.
  3. Week 3. Docker core concepts: virtualization, virtual machine against container, image, Dockerfile, Docker Hub, Docker Compose, Kubernetes. Followed the lecture and the slides.
  4. Week 4. Creating and managing Docker containers: image and container commands, run options, port mapping, MySQL and Metabase containers. Followed the lecture.
  5. Week 5. Python database connection 1: SQLite through sqlite3, cursor, connection pool, MySQL in a Docker container through pymysql, DDL and DML queries with commit. Followed the lecture.
  6. Week 6. Python database connection 2: SQLAlchemy create_engine for SQLite and MySQL, loading CSV files into tables with pandas to_sql, reading back with read_sql_table and read_sql, the with statement. Followed the lecture.
  7. Week 7. API calls with Python: HTTP requests, handling API responses, data collection.
  8. Week 8. Python classes and object-oriented basics.
  9. Weeks 9 to 11. Building a pipeline: ETL structure, managing sensitive information, extraction, cleaning and transformation, modularisation, loading, run control, logging.
  10. Weeks 12 to 16. Databricks basics, Apache Spark theory and code on Databricks, Delta Lake (Delta tables, ACID transactions), Databricks dashboards.

Hands-on work by the author (week 2):

  • What the exercise asked: create a virtual environment named myvenv, register it in VS Code, install five pinned libraries from a requirements.txt file, and run a given script from a notebook and from the command line as pip_venv_test.py.
  • What the author produced: a different environment, sm_python, made with python -m venv on Python 3.14.7. It holds two installed packages, click 8.5.0 and easydict 1.13, and req.txt lists the same two packages in the name==version form. It also holds test.py, which prints "hello", and test.ipynb, whose one cell did not run. No files for the five assigned libraries or for pip_venv_test.py were found.
  • No hands-on files were found for weeks 3 to 6.

Lesson

  1. Practised. A project gets its own Python environment made with python -m venv, and its packages are pinned as name==version. From week 2; shown by sm_python and req.txt.
  2. Practised; harder than expected. Making the environment is not enough for a notebook: VS Code must also use it as the kernel. The author's test.ipynb cell failed with the message that "Running cells with 'base (Python 3.14.7)' requires the ipykernel package", so it ran under the base Python, not sm_python. From week 2; shown by the saved error in test.ipynb.
  3. Studied. An image is the template and a container is a running copy; docker run options set the name, background mode, port mapping, volume and environment variables. From weeks 3 and 4, lectures only.
  4. Studied. Python reaches SQLite through sqlite3 and MySQL through pymysql, sending DDL and DML through a cursor and saving with commit. From week 5, lecture only.
  5. Studied. A SQLAlchemy engine lets pandas write a CSV into a table with to_sql and read it back with read_sql. From week 6, lecture only.
