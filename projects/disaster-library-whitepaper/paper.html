Disaster library whitepaper: from old newspaper reports to local disaster-prep handbooks

Abstract

Disasters repeat in the same places, and old newspapers record where. We describe a pipeline that extracts disaster events from mixed Hanja newspaper text by rules, matches each event to libraries within 5 km, groups events into risk zones with DBSCAN, pairs each zone with prevention research in three matching tiers, and drafts one handbook per zone named after its hub library. All results reported here come from a synthetic sample: 13 articles gave 12 events, 2 risk zones, 3 single sites, 15 paper matches and 5 handbook drafts. The pipeline has not been run on real data in the repository, and its LLM extraction path is untested. The handbooks leave evacuation advice to official guidance.

Overview

The project was entered in the National Library of Korea Library Data Competition 2026. It is a Python pipeline (run_pipeline.py, src/) that turns newspaper articles, a national library list in RDF and a set of research papers into handbook drafts for libraries near places where disasters repeat. The repository holds the code, synthetic sample inputs in data/sample/, and a full sample run in output/. Every article, paper and library in the sample is synthetic, marked [가상] in titles and "synthetic": true in records (docs/README.ko.md).

Problem define

The repository states the premise that disasters repeat in the same places and old newspapers remember where. That record is in mixed Hanja text, not in structured data that a nearby library could turn into a local handbook. The repository contains no measurement of the size of this problem on real data.

Process

Data. Synthetic old-newspaper articles in JSONL (data/sample/old_news.jsonl), a library list in RDF (data/sample/libraries.rdf), research papers in e-article JSON form (data/sample/e_articles.json) and a place-name dictionary (data/sample/gazetteer.csv). Place coordinates are approximate town centres.

Method. Extraction normalizes mixed Hanja text, including Hanja numerals (三千萬 to 30,000,000), then pulls date, disaster type, place and damage with rules and gives each event a confidence score (src/news_extract.py). Matching uses haversine distance to every library and keeps all within 5 km, or the nearest one if none (src/spatial.py). DBSCAN with haversine distance, eps 8 km and 2 minimum samples, finds risk zones, and the library closest to each zone is its hub (src/spatial.py). Papers are matched in three tiers: region and type, then type and terrain, then type only; a paper without the core keyword is dropped even if the region matches (src/paper_match.py). One handbook per zone has three parts: past record, risk factors, modern response (src/whitepaper.py).

Assumptions. Events are geocoded to town centres, so events in the same town fall on one point and a zone means disasters repeated in neighbouring towns. Only reported disasters are counted. The handbook does not write evacuation advice; it leaves a slot for the official guidance.

Validation. Events with confidence below 0.5 are set aside with a reason, and rejected articles are logged (output/rejected_articles.csv). Every draft ships with a checklist for expert review and carries the label that it must not be distributed before review (output/whitepapers/C00_SAMPLE-0001.md). No validation against real data or ground truth is recorded in the repository.

Lesson

The pipeline runs end to end, but only on synthetic data, so nothing here shows that it finds real repeat zones. The extraction rules are fitted to the sample's writing style; real OCR text with typos and vertical-writing traces would need more rules or the --llm option, and the --llm path and the e-article API source were not run-tested because no API key or specification was available (docs/README.ko.md). Geocoding to town centres limits spatial detail, and disasters the press did not report are absent.
